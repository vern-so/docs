---
title: Export CSV
description: Get a migration's data out as a clean CSV — addressed by template slug, downloaded or streamed straight into your own storage bucket, with optional column selection.
---

```http
GET https://app.vern.so/api/v1/migrations/{migration_id}/exports/{template_slug}.csv
```

Streams one sheet's data as a CSV, addressed by **template slug**.
This is synchronous — there's no run to poll. Columns come out in template order,
RFC 4180-escaped, and the body is streamed (gzip-compressed when your client
sends `Accept-Encoding: gzip`).

One call exports one sheet. To export a whole workbook, request each template's
slug in turn.

## Authentication

Requires an `x-api-key` header. See [Authentication](/migration-api/authentication).

## Path & query

<ParamField path="template_slug" type="string" required>
  The slug of the template whose sheet you want, with a `.csv` suffix — e.g.
  `contacts.csv`. [List your templates](/migration-api/list-templates) for slugs.
</ParamField>

<ParamField query="fields" type="string">
  Comma-separated column names to return, in the order you give them. Omit to
  return every column.

  Names are matched **exactly** and are case-sensitive — they're the same names
  that appear as CSV headers. An unrecognised name returns `400`
  (`unknown_field`) listing the valid ones, rather than being ignored: a typo
  should not quietly leave data out of your export.

  ```
  ?fields=Email,Company%20Name
  ```
</ParamField>

<ParamField query="omit_empty" type="boolean" default="false">
  Drop columns that hold no data.

  A column is dropped only when it's empty in **every** row, so the rows you get
  back all keep the same shape and the header still describes every one of them.
  Empty means an empty string, `null`, or an absent value — whitespace counts as
  data. Combine with `fields` and the pruning applies within your selection.

  This is answered from the completed import's stored per-column coverage, so it
  reflects the **whole sheet**, not just some sample. If that coverage isn't
  available — an older import, or one where profiling didn't run — the request
  returns `409` (`coverage_unavailable`) rather than quietly handing you every
  column and letting you believe it was pruned.
</ParamField>

## Response

`200 OK` with `Content-Type: text/csv; charset=utf-8` and a `Content-Disposition`
attachment header. The body is streamed. An `X-Total-Records` header reports the
sheet's total row count. When the request advertises gzip, the response is
gzip-encoded (`Content-Encoding: gzip`).

## Errors

| Status | Meaning |
|---|---|
| `400` | The path doesn't end in `.csv`, or `fields` names a column this template doesn't have. |
| `401` | API key missing or invalid. |
| `404` | No template with that slug, no sheet for it in this migration, or the migration isn't in your account. |
| `409` | The sheet uses compressed storage (use the [async export](/migration-api/export-jobs)); or `omit_empty` was asked for and this import has no per-column coverage; or every selected column turned out to be empty. |
| `429` | **30 requests per minute** per account (the Reads class). Check `Retry-After`. See [Rate limits](/migration-api/errors#rate-limits). |
| `500` | Server error. |

## Example

```bash
# every column (default)
curl "https://app.vern.so/api/v1/migrations/c0a8012e-.../exports/contacts.csv" \
  -H "x-api-key: $VERN_API_KEY" \
  -o contacts.csv

# just the columns you need, in your order
curl "https://app.vern.so/api/v1/migrations/c0a8012e-.../exports/contacts.csv?fields=Email,First%20Name" \
  -H "x-api-key: $VERN_API_KEY" \
  -o contacts-slim.csv

# skip the columns this import never populated
curl "https://app.vern.so/api/v1/migrations/c0a8012e-.../exports/contacts.csv?omit_empty=true" \
  -H "x-api-key: $VERN_API_KEY" \
  -o contacts-populated.csv
```

## Into your own storage

The endpoint hands you the file in the HTTP response — Vern doesn't push it
anywhere. To land the clean CSV in **your own bucket**, pull it from your backend
and pipe it straight into object storage. The body streams, so you never have to
buffer the whole file:

```bash
# Amazon S3
curl -s "https://app.vern.so/api/v1/migrations/c0a8012e-.../exports/contacts.csv" \
  -H "x-api-key: $VERN_API_KEY" \
  | aws s3 cp - s3://your-bucket/acme/contacts.csv

# Google Cloud Storage
curl -s "https://app.vern.so/api/v1/migrations/c0a8012e-.../exports/contacts.csv" \
  -H "x-api-key: $VERN_API_KEY" \
  | gcloud storage cp - gs://your-bucket/acme/contacts.csv
```

Any S3-compatible store (R2, MinIO, Spaces) works the same way. Keep your
`x-api-key` server-side — run this from your backend, never the browser. Vern
never receives your storage credentials; your backend relays the bytes.
