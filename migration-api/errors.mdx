Every Migration API endpoint shares one error model, one idempotency model, and
one rate limit.

## Status codes

| Status | Meaning |
|---|---|
| `400` | Malformed request — a required field is missing or a value is invalid (e.g. an unknown template slug, a bad `external_id`, an invalid run `kind`). |
| `401` | API key missing, malformed, or revoked. |
| `403` | The account has no active plan. Only on endpoints that create work — see [Plans](#plans). |
| `404` | The referenced migration, run, source, or template isn't in your account. |
| `409` | A conflict — a reused `external_id`, an ambiguous source name, a run already in progress, an [archived migration](/migration-api/manage-migrations#archive-a-migration) (`migration_archived`), an import in the way (`imports_in_flight`), or a state precondition (e.g. asking for the [session log](/migration-api/session-log) before the migration settles). |
| `412` | A guarded write lost a race. Only from [knowledge](/migration-api/knowledge) writes sent with `if_unmodified_since` — re-read, merge, and write again. |
| `413` | An [upload](/migration-api/upload-files) would take your account over its 50 GB storage limit (`storage_quota_exceeded`). |
| `421` | Wrong region: your account's data is hosted in another region. The body names the base URL to use — see [Data region](#data-region). |
| `422` | Knowledge is over its size limit (`knowledge_too_long`) — either the text you're saving, or knowledge a run would load, which stops the run from starting. |
| `429` | A [rate limit](#rate-limits) or the [concurrent-run limit](#concurrent-runs). Check `Retry-After`. |
| `500` | Server error — safe to retry idempotent requests. |
| `502` | The export worker couldn't be started. The [export job](/migration-api/export-jobs) is marked `failed`; queue a new one. |
| `503` | Temporarily unavailable — retry. Either document extraction is switched off (`DOCUMENT_EXTRACTION_DISABLED`, when you request a PDF, Word or image upload), or a transient failure: the session log or thread couldn't be loaded, or an answer, credentials or the go-ahead to execute couldn't be delivered to a waiting run. |

Run-level failures are different from request errors: a `POST /runs` request can
return `201` (accepted) and then resolve to a `failed` run. Read the run's
`error` field for the reason. See [Poll a run](/migration-api/poll-a-run).

## Error body

Every error response is a JSON object with a single human-readable `error`
string:

```json
{ "error": "external_id must be alphanumeric (hyphens/underscores allowed), max 255 chars" }
```

There's no field pointer or request-id header today, so branch on the HTTP
status and surface `error` for debugging. Where a status alone is ambiguous, the
body adds a machine-readable `code` — branch on that rather than on the message
text:

| `code` | Status | Meaning |
|---|---|---|
| `migration_archived` | `409` | The migration is [archived](/migration-api/manage-migrations#archive-a-migration). Uploads, runs, answers, credentials, knowledge, the source connection, cancelling and edits are refused; reads and exports still work. Restore it in Vern. |
| `imports_in_flight` | `409` | Archiving a migration, or changing its source or templates, while an import is in progress. `runs` lists the runs to cancel or wait for. |
| `run_concurrency_limit` | `429` | Your account already has 3 runs in progress — see [Concurrent runs](#concurrent-runs). |
| `instructions_too_long` | `400` | A `generate` run's `instructions` is over 200 characters. |
| `knowledge_too_long` | `422` | Knowledge is over its limit: 10,000 characters for source and migration knowledge, 5,000 for a template description. A save refusal carries `limit` and `length`; a refused run carries `documents[]`. |
| `storage_quota_exceeded` | `413` | Your account's uploads would go over 50 GB. Carries `usedBytes` and `limitBytes`. |
| `DOCUMENT_EXTRACTION_DISABLED` | `503` | Document extraction is currently unavailable, so PDF, Word and image files are refused. See [File limits](#file-limits). |
| `wrong_region` | `421` | Your account is hosted in another region — see [Data region](#data-region). |
| `unknown_field` | `400` | `fields` names a column that doesn't exist. The message lists the valid names. |
| `empty_field_selection` | `400` | `fields` was sent but empty. Omit it to get every column. |
| `invalid_field_selection` | `400` | `fields` in an export job body isn't an array. |
| `coverage_unavailable` | `409` | `omit_empty` on an export, but no completed import has per-column coverage to decide from. |
| `no_columns_selected` | `409` | No columns are left after `fields` / `omit_empty`. |
| `parquet_sheet_use_export_job` | `409` | The sheet uses compressed storage; use an [export job](/migration-api/export-jobs) instead of the CSV endpoint. |

## Rate limits

Limits are counted **per account**, not per API key or per IP — keys belonging to
the same account share one budget, and using a key from several machines doesn't
multiply it.

Each endpoint belongs to one of four classes, sized to what it costs us to
serve:

| Class | Limit | Endpoints |
|---|---|---|
| **Reads** | 30 / minute | [Listing and getting migrations](/migration-api/manage-migrations), polling a run, the preview, the session log, the thread, listing files, reading knowledge and the source connection, export job status and CSV downloads, listing and reading sources and templates |
| **Writes** | 30 / minute | [Updating and archiving a migration](/migration-api/manage-migrations), [cancelling a run](/migration-api/poll-a-run#cancel-a-run), writing knowledge, pinning a source, creating or removing a source connection, editing a template or source, [requesting upload URLs](/migration-api/upload-files) |
| **Jobs** | 15 / hour | [Starting an export](/migration-api/export-jobs) |
| **Agent** | 30 / hour | [Starting a run](/migration-api/start-a-run), [answering questions](/migration-api/answer-questions), [submitting credentials](/migration-api/submit-credentials) |

Two actions also have their own hourly cap, because each one provisions
something new:

| Action | Limit |
|---|---|
| [`POST /migrations`](/migration-api/create-a-migration) | **30 per hour** |
| [`POST /migrations/{id}/runs`](/migration-api/start-a-run) with `kind: "generate"` | **30 per hour** |

Starting a run with `kind` of `update`, `clarify` or `execute` does not count toward
that cap — those continue a run you've already started rather than beginning
new work — but they do count against the **Agent** class above.

<Note>
The read budget assumes the documented polling cadence of
[~10 seconds](/migration-api/poll-a-run) across up to
[3 concurrent runs](#concurrent-runs), which is 18 requests per minute, leaving
room for previews and logs. If you poll faster you will hit the limit without
learning anything sooner — use the
[thread stream](/migration-api/stream-the-thread) for live progress instead.
</Note>

There is an additional per-IP ceiling that absorbs bursts before authentication.
It is deliberately not published: it sits well above these per-account limits and
you will not meet it through normal use.

Over any limit you get a `429`:

```json
{ "error": "Too many requests" }
```

`429` responses carry headers you should prefer over guessing:

| Header | Meaning |
|---|---|
| `Retry-After` | Seconds until the window resets. Wait this long. |
| `X-RateLimit-Limit` | The limit for this bucket. |
| `X-RateLimit-Remaining` | Requests left in the current window. |
| `X-RateLimit-Reset` | Unix timestamp (seconds) when the window resets. |

Space your run polling out so a fleet of concurrent migrations doesn't burn the
read budget on status checks — or switch to the
[thread stream](/migration-api/stream-the-thread), which doesn't spend a read per
update.

## Concurrent runs

An account may have at most **3 runs in progress at a time**, across every
migration. This is separate from the per-migration rule — one run at a time per
migration — and applies on top of it.

Only runs that are actually working count: `queued`, `running`, and `blocked`
(waiting on your answer). A run sitting in `awaiting_approval` is waiting on you,
not consuming capacity, so it doesn't count against the limit.

Exceeding it returns `429` with a machine-readable code and the runs responsible:

```json
{
  "error": "You already have 3 imports running, which is the limit. Wait for one to finish, or stop one to start another.",
  "code": "run_concurrency_limit",
  "limit": 3,
  "runs": [
    { "id": "run_...", "status": "running", "updatedAt": "2026-10-01T09:14:22.000Z", "runKind": "generate" }
  ]
}
```

Wait for one to finish, or cancel one, then retry.

## File limits

A migration run is bounded by how many files it consumes, not by how many you
upload over its lifetime:

| Limit | Value |
|---|---|
| Documents (PDF, Word and image files) per run | **5** |
| Files of any kind per run | **400** |
| Files per upload request | **25** |
| Uploaded storage per account | **50 GB** |

Only **documents** count toward the first limit — PDF (`.pdf`), Word (`.docx`)
and images (`.png`, `.jpg`, `.jpeg`, `.tif`, `.tiff`). They go through document
extraction, which is the expensive path. Spreadsheets and CSVs (`.csv`, `.xlsx`,
`.xls`, `.xlsm`, `.xltx`, `.xltm`), SQL dumps (`.sql`, `.bak`), XML exports
(`.xml`) and ZIP archives (`.zip`) are also accepted; they don't count toward it,
only toward the 400.

<Warning>
  Document extraction is currently unavailable. While it is, documents are
  refused at upload with `503` and `code: "DOCUMENT_EXTRACTION_DISABLED"`, and
  documents inside a ZIP are dropped and listed as skipped. Everything else
  works as normal.
</Warning>

The per-request limit applies to a single
[`POST /migrations/{id}/files`](/migration-api/upload-files) call. It is not a
ceiling on the migration — request URLs in batches of 25 and upload as many
times as you need, up to the 400 total.

Over a count limit you get a `400` naming which limit was hit and what the run
would have totalled; over the storage limit, a `413` with
`code: "storage_quota_exceeded"`.

## Plans

The endpoints that create work — [`POST /migrations`](/migration-api/create-a-migration),
[starting a run](/migration-api/start-a-run) and
[starting an export](/migration-api/export-jobs) — require an active
subscription, and return `403` without one:

```json
{ "error": "Your plan does not include data imports. Upgrade your plan to import data." }
```

Reads are unaffected, so an account between plans can still retrieve what it
already has.

## Idempotency

Migration **creation** is idempotent on the `external_id` you choose. Re-sending
[`POST /migrations`](/migration-api/create-a-migration) with the same `external_id`
(and the same source) returns the **existing migration** — with a `200` instead
of a `201` — rather than creating a second one. This makes create retries safe
and doubles as recovery: if you lose a migration ID, re-POST with the same
`external_id` to get it back, or look it up with
[`GET /migrations?external_id=…`](/migration-api/manage-migrations#list-migrations).
If that migration is archived, the re-POST answers `409` with
`code: "migration_archived"` and its `id`.

Runs are **not** keyed by an idempotency token. Instead, only **one run runs at a
time per migration** — starting a second while one is in flight returns `409` with
the active `run_id`, which is how you recover a run you lost track of. See
[Start a run](/migration-api/start-a-run). Across migrations, an account is also
capped at [3 runs in progress](#concurrent-runs).

## Polling conventions

- Poll runs about every 10 seconds, backing off as the run ages — the
  [Reads budget](#rate-limits) is sized for that.
- Treat `awaiting_approval`, `completed`, `failed`, and `canceled` as terminal
  for a given run; stop polling.
- Make your handling idempotent — the same terminal state can be read more than
  once.
- Prefer the [thread stream](/migration-api/stream-the-thread) (SSE) over tight
  polling when you want live progress.

## Data region

Migrations are created in your **account's region**, and your account's requests
are processed in that region. Each region has its own base URL:

| Account hosted in | Base URL | MCP server |
|---|---|---|
| United States | `https://app.vern.so/api/v1` | `https://app.vern.so/api/mcp` |
| Australia | `https://au.app.vern.so/api/v1` | `https://au.app.vern.so/api/mcp` |

A key used against the other region's base URL is refused with `421 Misdirected
Request` before any work happens. The body tells you where to send it:

```json
{
  "error": "This account's data is served from https://au.app.vern.so. Use https://au.app.vern.so/api/v1 for API calls.",
  "code": "wrong_region",
  "region": "syd",
  "base_url": "https://au.app.vern.so/api/v1",
  "mcp_url": "https://au.app.vern.so/api/mcp",
  "app_url": "https://au.app.vern.so"
}
```

Switch your client's base URL to `base_url` and retry. Don't retry against the
same URL: the answer won't change.

If you need data to land in a specific region for residency reasons, talk to us at
[roupen@vern.so](mailto:roupen@vern.so) — additional regions are enabled per account.
